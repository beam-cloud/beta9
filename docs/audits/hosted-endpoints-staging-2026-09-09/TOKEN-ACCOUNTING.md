# Hosted token accounting

The gateway records completed engine requests in integer micro-US dollars. `prompt_tokens` includes `cached_tokens`; the input cost bills only the uncached portion. Output, cached input, requests, and images retain separate costs at the price used for that request. A missing cache discount uses the ordinary input price while keeping cache usage separately visible. The request total rounds once to the nearest micro-dollar; largest fractional components receive the rounding remainder, so the components always sum to the actual charge.

Before returning a successful JSON response or the streaming `[DONE]` marker, the gateway journals the immutable generation and applies its usage. Redis daily workspace/model counters and the deduplication marker commit in one validated Lua script. A pending journal survives gateway restarts and has no expiry until buyer spend and provider earnings are both applied. The background meter retries pending accounting every five seconds. Invalid counters or overflow fail before any increment; a missing billing meter never silently deletes pending data.

Billing reads these canonical counters directly using its dedicated `REDIS_*_BETA9` connection. It verifies `managed_endpoint:accounting:schema=2`, fails on malformed data or unavailable storage, and uses explicit UTC days that have not already settled. Closed-day settlement refuses a day with older pending accounting journal entries. This avoids adding eventually consistent OpenMeter usage to an overlapping live total. OpenMeter remains an idempotent asynchronous export; its cost event also contains the exact token and cost breakdown. Undelivered buckets do not expire.

The Usage API exposes token and cost components in the total, per-model, and per-day reports. Historic requests that only stored total cost remain unitemized; they are never repriced from current catalog rates. The Usage page refreshes completed-request usage and available credits every five seconds while visible. The credit ledger preserves fractional cents; whole-cent daily rounding is removed.

Limits: engine usage is final at request completion, not estimated token by token while a stream is in flight. Concurrent requests do not reserve their future maximum cost. The existing admission cache and minimum-credit policy remain relevant to enforcement. A micro-dollar is the request's billing precision, so sub-micro-dollar rounding still exists. Redis durability and persistence remain operational requirements; the journal protects process restarts and retryable writes, not total loss of the accounting datastore.
